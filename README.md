# 부스메이트 (Boothmate) — React 프론트엔드 데모

현장 판매 부스에서 번호표 확인과 굿즈 사전 주문을 통해 대기·운영 시간을 줄이기 위한 **React + Vite** 웹앱입니다. JavaScript와 CSS만 사용했으며 **별도의 서버, 실제 데이터베이스, 결제 시스템은 없습니다.**

## 설치 · 실행

```bash
npm install
npm run dev
```

터미널에 표시되는 주소(기본 `http://localhost:5173`)를 엽니다. 프로덕션 빌드 확인은 `npm run build`로 실행할 수 있습니다.

### 태블릿/모바일에서 열기

같은 Wi-Fi에 연결된 컴퓨터와 태블릿/휴대폰을 준비합니다. 개발 서버는 `--host 0.0.0.0`으로 실행되도록 설정되어 있습니다. 터미널에 표시되는 **Network 주소**(`http://컴퓨터-LAN-IP:5173`)를 모바일 브라우저에서 열어 보세요. PC 방화벽이 해당 포트를 막으면 허용해야 합니다.

> **주의:** 지금 프로젝트는 `localStorage`로 작동합니다. 컴퓨터와 태블릿에서 같은 주소로 접속해도 **번호표/주문 정보는 동기화되지 않습니다.** 실제 현장에서 여러 기기를 동시에 사용하려면 백엔드와 공유 데이터베이스가 꼭 필요합니다.


## 구현 기능

### 방문객
- 메인: 부스 검색, `운영 중/오픈 예정/운영 종료` 필터, 시작일·종료일 기간 필터
- 부스: 소개, 행사 시간/위치, 굿즈 종류·가격·잔여 재고
- 참가자 명단/참가자 개별 소개, SNS 서비스 링크(시연용 예시)
- 번호표 조회: `번호 + 이름 + 코드`를 검증하고 주문 UI 잠금 해제
- 사전 주문: 수량 선택, 재고 검증 및 차감, 주문 접수
- 내 주문내역: 조회한 번호표에 연결된 주문과 운영자 처리 상태 확인

### 부스 운영자
- 데모 로그인/회원가입, 소속 부스 선택
- 관리 대시보드: 발급 번호표, 주문, 주문 금액, 남은 재고 요약
- 인원 관리: **현장대기 / 추후소집** 유형별 동일한 발급·인증 UI, 서로 독립된 번호 체계
- 번호표 발급: 이름 입력 → 자동 번호 + 임의 6자리 인증 코드 발급
- 번호표 인증: 번호·이름·코드 확인 후 확인 완료 상태로 변경
- 판매 관리: 접수 → 준비 중 → 수령 완료, 상품 재고 요약
- 설정: 부스 이름·소개·위치·운영 일정, 두 번호표 시작 번호, 상품 추가/편집/삭제 및 재고 수정
- 데모 데이터 전체 초기화

## 폴더 구조

```text
src/
  main.jsx               # React 진입점
  App.jsx                         # 라우팅에 따라 페이지 연결
  hooks/useHashRoute.js           # 해시 URL 이동 관리
  hooks/useBoothApp.js            # 번호표, 주문, 재고 상태/작업
  components/AppNavigation.jsx    # 헤더 + 태블릿/모바일 하단 메뉴
  components/UI.jsx               # 공통 버튼, 카드, 입력폼, 모달
  pages/public/                   # 방문객 화면 (화면별 JSX 파일)
  pages/admin/                    # 운영자 화면 (화면별 JSX 파일)
  pages/PublicPages.jsx           # 방문객 화면 내보내기
  pages/AdminPages.jsx            # 운영자 화면 내보내기
  styles.css                      # 모든 크기의 기본 스타일
  responsive.css                  # 태블릿(880px) · 모바일(650px) 반응형
  lib/demo.js                     # 샘플 부스 데이터, 유틸리티, 저장소 키
```

### 데이터 흐름
1. `hooks/useBoothApp.js`에서 `useState(loadDB)`로 초기 상태를 불러옵니다.
2. 번호표 발급·인증, 주문 등의 함수가 `setDb()`로 React 상태를 갱신합니다.
3. `useEffect()`가 수정된 값을 브라우저 `localStorage`에 저장합니다.
4. 로그인 세션과 조회한 번호표 목록은 브라우저 `sessionStorage`에 저장됩니다.
5. `hooks/useHashRoute.js`가 URL 해시(`#/booth/moon`, `#/admin/moon/people`)를 감지하고, `App.jsx`에서 페이지를 고릅니다. React Router는 필요하지 않습니다.

## 중요한 한계 (상용 서비스 전환 시 필수 작업)

**현재는 교육·시연용 프론트엔드만 구현되어 있습니다.** 브라우저의 localStorage에는 데이터 격리·권한 통제·동시 수정 방지 기능이 없고, 샘플 계정의 비밀번호도 평문으로 존재합니다. **실제 고객의 개인정보를 입력하지 마세요.**

실서비스 전환 시 아래 작업이 필요합니다.
- 백엔드 DB 및 API (부스, 운영자, 소속 권한, 번호표, 주문, 상품)
- 안전한 사용자 인증, 비밀번호 해싱, 관리자 초대/권한 체크
- 개인정보 동의·보관·파기 정책과 접근 통제
- 동시 주문 시 재고가 음수가 되지 않도록 트랜잭션/예약 처리
- 주문 취소·재고 복구, 품절 처리, 정산 또는 결제 기능
- 실제 SNS 프로필 URL, 서버 시간 기반 운영 기간 판정
- 번호표 QR/바코드 및 현장 확인 흐름(선택 사항)

현재 시연 중인 주문은 **결제 없이 재고만 즉시 차감**되며, 번호표는 운영자가 발급하고 방문객이 조회해야 주문할 수 있습니다.

## 모바일/태블릿 UI 개선사항

- **880px 이하:** 상단은 접이식 메뉴, 하단은 `부스 찾기 / 주문내역 / 부스 관리` 빠른 메뉴로 바뀝니다.
- **650px 이하:** 1열 부스 카드, 가로로 넘기는 운영 상태 필터, 간격을 늘린 버튼과 수량 조절 UI, 아래에서 올라오는 번호표 발급/편집 모달을 사용합니다.
- 운영자 인원 관리의 표는 좌우 스크롤로 나머지 컬럼을 확인할 수 있습니다.
- 화면 아래 고정 메뉴는 iOS 홈 인디케이터 영역(`safe-area-inset-bottom`)을 피합니다.
- 버튼에 키보드 포커스 스타일을 추가했고, 애니메이션 감소 설정을 따릅니다.
